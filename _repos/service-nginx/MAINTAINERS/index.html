    Maintainers

    This document lists the maintainers of the Open Horizon Nginx Service project.

    Current Maintainers

    Joe Pearson

    • GitHub: @joewxboy
    • Email: joe.pearson@us.ibm.com
    • Organization: IBM
    • Role: Project Lead & Primary Maintainer
    • Responsibilities:
    • Overall project direction and architecture
    • Code review and merge approval
    • Release management
    • Community engagement and support
    • Security issue coordination

    Maintainer Responsibilities

    Maintainers are responsible for:

    1. Code Quality
    2. Review and approve pull requests
    3. Ensure code meets project standards
    4. Maintain test coverage

    5. Keep dependencies updated

    6. Documentation

    7. Keep documentation accurate and up-to-date
    8. Review documentation contributions

    9. Ensure examples work correctly

    10. Community

    11. Respond to issues and questions
    12. Foster a welcoming environment
    13. Recognize and encourage contributors

    14. Coordinate with Open Horizon community

    15. Releases

    16. Plan and execute releases
    17. Maintain changelog
    18. Tag versions appropriately

    19. Coordinate with downstream users

    20. Security

    21. Address security vulnerabilities promptly
    22. Coordinate security disclosures
    23. Keep dependencies secure
    24. Follow security best practices

    Decision Making

    Minor Changes

    • Documentation updates
    • Bug fixes
    • Small feature additions
    • Dependency updates

    Process: Single maintainer approval required

    Major Changes

    • Architecture changes
    • Breaking changes
    • New major features
    • Policy changes

    Process: Consensus among maintainers required

    Emergency Changes

    • Critical security fixes
    • Service outages
    • Data loss prevention

    Process: Any maintainer can act immediately, notify others ASAP

    Becoming a Maintainer

    We welcome new maintainers who have demonstrated:

    1. Sustained Contribution
    2. Regular, high-quality contributions over 6+ months
    3. Multiple merged pull requests

    4. Active participation in discussions

    5. Technical Expertise

    6. Deep understanding of the codebase
    7. Knowledge of Open Horizon platform

    8. Understanding of edge computing concepts

    9. Community Engagement

    10. Helpful responses to issues
    11. Constructive code reviews

    12. Positive community interactions

    13. Alignment with Project Goals

    14. Understanding of project vision
    15. Commitment to project values
    16. Availability for maintainer duties

    Nomination Process

    1. Self-Nomination or Nomination by Current Maintainer
    2. Open an issue titled "Maintainer Nomination: [Name]"

    3. Include contribution history and qualifications

    4. Discussion Period

    5. 2-week discussion period
    6. Current maintainers evaluate nomination

    7. Community feedback welcome

    8. Decision

    9. Consensus among current maintainers
    10. Nominee notified of decision
    11. If approved, added to this document

    Maintainer Emeritus

    Maintainers who step down are recognized as Maintainer Emeritus:

    • Listed in acknowledgments
    • Retain commit access (optional)
    • Welcome to return as active maintainer
    • Continued recognition for contributions

    Process for Stepping Down

    1. Notify other maintainers
    2. Transfer active responsibilities
    3. Update this document
    4. Optional: Retain commit access
